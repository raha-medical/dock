# متطلبات الواجهات (UI/UX) — مجمع الرحمة
## ملف التسليم لفريق الفرونت

هذا الملف يجمع **كل** متطلبات الواجهات التي طلبها صاحب المشروع، من ملف المتطلبات (`requirements-report.md`) ومن القرارات التي اتُّخذت أثناء جلسات العمل. كل بند له رقم وشرط قبول. **لا يُعتبر العمل منتهياً حتى يتحقق كل بند.**

---

## قواعد العمل (إلزامية)

1. العمل على فرع `ui/redesign` من `staging` في مستودع frontend، والدمج عبر Pull Request إلى `staging`.
2. **لا يُعدَّل** منطق الشاشات ولا استدعاءات الـ API ولا الـ backend. التصميم فقط.
3. الثيم والألوان والخطوط والمكونات العامة (الأزرار، البطاقات، الحوارات، الجداول) ملك فريق الفرونت.
4. البناء فوق الموجود. لا تُعاد كتابة شاشة تعمل وظيفياً؛ يُعاد تصميم شكلها فقط.
5. كل شاشة تُختبر بالعربية (RTL) والإنجليزية (LTR)، وعلى الحاسوب (1440px) والهاتف (390px).
6. المرجع للبيانات والنقاط: عقود الـ API `api_contracts.md` ووثيقة التسليم `frontend-handoff-v1.1.md`.

## منهجية العمل مع وكيل الجودة (QA)

نفس المنهجية التي اتُّبعت في الخادم: **تدقيق أولاً، ثم إصلاح، ثم تحقق.** لا يبدأ التصميم قبل التدقيق.

وكيل الجودة معرَّف في الملف `ui-qa.md`، وهو مهندس QA أول، يختبر ويكتب تقريراً ولا يعدّل الكود.
- **إذا كان الفريق يستخدم Claude Code:** يوضع الملف في `.claude/agents/ui-qa.md` داخل مستودع frontend، ويُستدعى بالاسم `ui-qa`.
- **إذا كان يستخدم أداة أخرى:** يُفتح لوكيل الجودة جلسة أو محادثة منفصلة، ويُعطى محتوى `ui-qa.md` كتعليمات أولى. المهم أن يكون **منفصلاً** عن النموذج الذي يكتب الكود، حتى يكون حكمه مستقلاً.

### المرحلة 1: التدقيق (بدون أي تعديل)
1. تشغيل النظام كاملاً من الوسم `v1.1-handoff`.
2. وكيل الجودة يختبر كل الشاشات، ويقارنها بالبنود UI-01 إلى UI-118.
3. الناتج: `audit-ui.md`، وفيه لكل بند: الحالة (متحقق / جزئي / غير متحقق)، ولكل مشكلة: الشاشة، والدور، واللغة، والعرض، واللقطة، والخطورة (حرجة / عالية / متوسطة / منخفضة).
4. **مراجعة التقرير مع صاحب المشروع قبل البدء.**

### المرحلة 2: الأسس
الثيم (الألوان، الخطوط، المسافات)، والمكونات العامة، والأيقونات، والتنقل (القائمة الجانبية وأشرطة التنقل). لأن كل الشاشات تُبنى عليها.

### المرحلة 3: الشاشات
بالترتيب: شاشات الدخول، ثم الطابور والتحصيل والحساب اليومي، ثم تطبيق المراجع، ثم الأقسام المساندة، ثم الإعدادات والدعم.

### المرحلة 4: التحقق بعد كل مجموعة شاشات
وكيل الجودة يختبر **الشاشات المعدّلة فقط**. كل مشكلة حرجة أو عالية تُصلح، ثم يُعاد اختبارها، قبل الانتقال للمجموعة التالية.

### المرحلة 5: الفحص الشامل الأخير
وكيل الجودة يختبر النظام كله مرة واحدة، ويكتب حكمه: جاهز للإطلاق أم لا. ثم يُفتح الـ Pull Request.

### لتوفير الوقت في اللقطات
- تطبيق المراجع: عرض 390 فقط.
- لوحة الموظفين: عرض 1440 لكل الشاشات، و 390 لشاشات الدخول والتحصيل والتنقل فقط.
- الإنجليزية: لشاشات الدخول والتنقل والحجز فقط. العربية لكل الشاشات.
