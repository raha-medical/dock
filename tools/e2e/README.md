# اختبارات E2E لمجمع الرحمة

تعمل بلا مكتبات إضافية: Node 24 و Chrome بلا واجهة. على قاعدة `alrahma_db` المحلية فقط. **تضيف بيانات اختبار ولا تحذف شيئاً.**

## قبل التشغيل
1. الباك اند على 8088 (انظر `docs-e2e/تقرير_المرحلة_A_والمتبقي.md`).
2. الواجهة على 3000. يُفضل البناء النهائي: `npx next build` ثم `npx next start -p 3000`.
3. محاكي الطابعة والدرج: `node tools/agent-simulator/agent-sim.mjs`.
4. الملف `DEV_ACCOUNTS.local.txt` في الجذر.

## التشغيل من الجذر
```bash
node tools/e2e/crawl.mjs
node tools/e2e/flows.mjs
```

- **`crawl.mjs`:** يدخل بكل دور عبر الواجهة، ويمر على كل شاشة بعرضي 1280 و400، ويسجل أخطاء JavaScript وطلبات API الفاشلة والشاشات الفارغة والتمدد الأفقي.
- **`flows.mjs`:** رحلة كاملة بالنقر الفعلي من حساب مريض جديد حتى الكشف المالي والإدارة، مع تحقق من القاعدة في الخطوات المهمة. لتشغيل مجموعة واحدة: `node tools/e2e/flows.mjs patient`.

النتائج في `tools/e2e/out/`: ملف JSON لكل تشغيل، وصورة `fail-*.jpg` لكل خطوة فاشلة.

## حدود هذه الاختبارات
- الدخول المتكرر برقم هاتف واحد يصطدم بحد طلبات الرمز، لذلك كل تشغيل يولّد أرقاماً جديدة.
- الكاميرا والميكروفون والخرائط الخارجية لا تُختبر هنا. مسح QR يُجرَّب بإدخال الرمز نفسه من واجهة الإدخال.
- لا تختبر بوابة الدفع الحقيقية ولا SMS ولا Firebase ولا Gemini ولا رفع الملفات.
